# 酒店供应链采购平台 UI 第三轮视觉重构计划 V1

## 1. 本轮结论

第二轮已经完成脚本层面的验收，但没有通过人工商业视觉验收。当前页面仍然存在后台模板感：登录页像通用 SaaS 双栏模板，工作台仍以卡片和 KPI 横条为主，侧边栏像目录组件，状态标签和操作按钮堆叠明显。

本轮目标不是继续调色，而是固定关键屏的产品结构，让第一眼更接近真实酒店集团采购系统。

## 2. 本轮优先级

1. 登录页：从营销式双栏卡片改成政企门户式登录。
2. AppShell：弱化侧边栏组件感，减少顶部按钮堆叠。
3. 采购经办工作台：以待处理业务表格为主，摘要只做辅助，不再像 KPI 矩阵。
4. 右侧信息栏：风险和常用操作改成紧凑业务清单，不再是按钮/标签堆叠。
5. 检查脚本：新增能拦截模板化问题的规则，不能只验证类名存在。

## 3. 禁止再次出现

- 登录页大面积空白 + 右侧孤立白卡。
- “今日业务台账”这类模板化 KPI 卡片标题。
- 工作台首屏超过 4 个主要面板。
- 工作台主表格出现横向滚动条。
- 右侧常用操作使用整行按钮堆叠。
- 风险提醒全是同色大标签。
- 顶部栏消息、账号、安全都像主操作按钮。
- 为了截图 PASS 而隐藏真实问题。

## 4. 验收标准

自动化验收仍然保留：

```bash
npm run typecheck
npm run ui:copy-scan
npm run ui:commercial-check
npm run ui:visual-evidence
npm run ui:login-role-smoke
npm run ui:layout-check
npm run sellable:check
```

新增人工判断口径：

- 登录页在 1366x768 下像企业系统入口，不像营销页模板。
- 采购工作台首屏主角是待处理事项，不是 KPI 卡片。
- 侧边栏是轻量业务导航，不像后台模板目录。
- 无横向滚动条、无按钮堆叠、无大面积空白。
- Production 可以继续 NO_GO，但原因不能是 UI 商业质感不足。
