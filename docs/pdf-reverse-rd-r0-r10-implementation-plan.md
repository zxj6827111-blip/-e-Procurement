# 酒店供应链平台 PDF 逆向研发 R0-R10 实施方案

> 版本：V1.1  
> 日期：2026-06-25  
> 目标：在不浪费现有系统成果的前提下，基于当前 Vue + Express + TypeScript 工程继续补齐能力，最终逐步对齐《白天鹅连锁酒店供应链项目演示 - 202506.pdf》中展示的酒店集团供应链协同与阳光采购平台形态。本文同时作为后续开发与最终验收的目标功能对照基线。

## 一、总体结论

当前系统不能按“PDF 逆向完整系统”认定完成。它已经具备招采主链、文件中心、权限审计、项目工作台和基础商城域，但距离 PDF 中展示的完整系统仍有明显差距，尤其体现在：

- 页面可用性：部分上传、图片预览、删除、编辑、作废、撤回等操作不完整。
- 业务深度：供应商全生命周期、商品中心、询价、招标答疑、样品、定价报告、商城、结算资金、审批流等仍需补齐。
- 数据治理：部分对象仍是过渡结构或演示数据，尚未全部成为可治理业务表。
- 生产能力：正式数据库、SSO/OA/ERP/WMS/财务/合同接口、对象存储、监控、备份、安全测试仍未完成。

因此后续路线不是推倒重写，而是保留已有基础，按 R0-R10 分阶段补齐。

## 二、保留和复用现有系统

后续研发必须复用以下已有能力：

- 现有前端骨架、路由、页面布局和业务入口。
- 现有后端 Express API、类型定义、运行配置、测试体系。
- 已有登录、会话、权限、文件上传下载、文件版本、审计日志能力。
- 已有供应商、采购申请、公告邀请、报价、专家评审、定标、订单、收货、结算、档案等主链实现。
- 已有项目工作台、文件中心、供应链商城、权限配置等页面。
- 已有阶段 1-11 的测试与本地验证结果。

禁止为了追求“重新设计”而废弃现有可用成果。除非某块能力已经阻碍继续扩展，否则采用渐进式补齐。

## 四、最终模块功能与字段验收基线

本节按模块定义最终系统应具备的功能和字段。字段名称可根据现有代码命名调整，但页面展示必须使用中文业务含义。

### 1. 供应商注册与准入

目标功能：

- 供应商账号注册、登录、企业资料维护。
- 潜在供应商登记。
- 资质初审、准入评估、转正。
- 考核评价、等级、黑名单/禁用。
- 资质、营业执照、授权书、工厂资料、图片上传。
- 封样登记和封样图片。

核心字段：

- 供应商编码、供应商全称、企业简称、供应商类型、供应商来源、供应商性质。
- 统一社会信用代码、营业执照号、法定代表人、企业性质、注册资本、注册地址。
- 业务范围、供货品类、服务区域、供货区域、酒店品牌。
- 联系人、职位、手机号、座机、传真、邮箱。
- 开户行号、开户行全称、户名、纳税信息、财务资料。
- 资质状态、审核人、审核时间、审核意见、准入评分、准入结果、供应商等级。
- 封样名称、款式、说明、图片、接收人、接收时间。

### 2. 商品资料与定价

目标功能：

- 商品新建、编辑、删除/停用。
- 商品图片、详情图、图文详情、验收指引。
- 商品分类、品牌、规格、单位、装箱数量、最大/最小订货量。
- 税务开票信息。
- 销售定价、服务费率、毛利、对标价、历史价。
- 上架、下架、隐藏、排序。
- 供应商报价单和供货区域。

核心字段：

- 产品编码、产品名称、产品分类、产品品牌、酒店品牌、产品性质。
- 规格说明、单位、装箱数量、最大订货量、最小订货量。
- 用途、标签、是否安装、运费说明、备货金比例。
- 税率、税收分类编码、开票名称、开票规格说明。
- 产品主图、详情图、商城图文详情、验收指引。
- 采购价、销售价、平台价、网络价、完全对标价、参考对标价、历史价。
- 服务费率、保底服务费率、封顶服务费率、成本价、毛利润、毛利率。

### 3. 采购申请、询价与招标

目标功能：

- 采购申请创建、编辑、提交、审批、取消。

- 询价单创建、多轮报价、供应商邀请、截止控制、报价汇总。
- 招标发起、公告、投标人须知、评标办法、文件要求、供应商报名、资格审查。
- 招标提问答疑、样品接收。

- 招标编号、招标标题、酒店品牌、招标类型、招标公告、投标人须知、评标办法。
- 价格评分权重、技术评分权重、商务评分权重、供应商资格条件、文件要求、必传标识。

### 4. 供应商应标、专家评审与定标

目标功能：

- 供应商接收邀请、开始应标、放弃应标。
- 应标报价、资质文件上传、商务/技术/报价文件上传。
- 应标提交后锁定，保留版本。
- 截标前报价保密，截标后按权限查看。
- 专家维护、专家分配、评审范围、评分模板。
- 专家评分、提交锁定、受控复评、评分汇总。
- 定标推荐、定标审批、结果通知、内部公示或备案。
- 定价报告生成。

核心字段：

- 应标编号、招标 ID、供应商 ID、应标状态、开始应标时间、提交时间、放弃原因。
- 联系人、联系电话、默认税率、报价商品、含税价、不含税价、供应数量、交货天数、质保期。
- 供应品牌/型号、产品描述、报价说明、文件要求、上传文件、提交版本。
- 提问内容、答疑内容、是否公开、答疑附件。
- 专家姓名、账号、评标范围、评审类型、评分模板、评分项目、参考标准、分值、得分、备注。
- 定标报告、候选供应商、选定供应商、中标商品、定标总结、审批状态。

- 商城首页、分类筛选、商品详情、加入购物车。

- 订单支付或模拟支付。
- 供应商发货、物流登记、发货单附件。
- 酒店收货、验收图片、异常收货、补录。
- 订单评价、退货申请、退货审核、供应商确认。

核心字段：

- 商品 ID、商品名称、图片、分类、品牌、规格、单位、价格、最小订货量、可供区域。
- 购物车 ID、酒店 ID、商品 ID、数量、单价、金额。
- 订单编号、下单酒店、供应商、收货地址、订单金额、支付状态、履约状态。
- 发货单号、物流公司、物流单号、发货时间、发货数量、发货附件。
- 收货数量、验收结果、验收图片、异常说明、补录记录。

## 五、全角色流程验收脚本

最终验收必须按角色跑通，不允许只用管理员账号验收。

### 1. 酒管集团管理员

验收脚本：

1. 登录系统。
2. 维护组织、酒店、品牌、区域、角色、用户。
3. 配置审批流程。
4. 配置商品分类和全局参数。
5. 查看审计日志和流程日志。

通过标准：

- 能配置主数据和流程。
- 不能代替供应商提交报价。
- 敏感业务操作有审计记录。

### 2. 酒管采购管理员

验收脚本：

1. 登记潜在供应商。
2. 审核供应商资质并准入。
3. 创建采购申请并审批通过。
4. 发起询价或招标。
5. 发布公告、邀请供应商、审核报名。
6. 截标后查看报价和评审结果。
7. 完成定标并生成定价报告。

通过标准：

- 采购寻源全流程可跑通。
- 截止前看不到供应商报价金额或响应文件实质内容。
- 所有关键动作有日志。

### 3. 酒店/门店采购人员

验收脚本：

1. 创建或提交采购需求。
2. 进入商城选品。
3. 查看商品图片、价格、详情。
4. 加入购物车并下单。
5. 收货验收、上传图片。
6. 提交订单评价或退货申请。

通过标准：

- 只能看到本酒店或授权范围数据。
- 商品可筛选、可下单。
- 收货、评价、退货状态正确流转。

### 4. 酒店财务人员

验收脚本：

1. 查看酒店余额和授信。
2. 发起充值或授信申请。
3. 审核订单支付。
4. 核对供应商结算。
5. 审核发票。

通过标准：

- 资金流水、订单金额、结算金额、发票金额能勾稽。
- 财务只能操作财务相关事项。

### 5. 供应商管理员

验收脚本：

1. 注册企业。
2. 维护企业资料、联系人、资质、供货区域。
3. 上传营业执照、授权书、资质文件、图片。
4. 查看本企业订单。
5. 发货、处理退货、提交结算资料、上传发票。

通过标准：

- 只能看到本企业数据。
- 不能看到其他供应商报价、文件、订单、结算。
- 上传文件可预览、下载、替换、作废。

### 6. 供应商报价人员

验收脚本：

1. 查看询价或招标邀请。
2. 开始应标。
3. 提交报价。
4. 提问并查看答疑。
5. 上传资质、商务、技术、报价文件。
6. 提交应标。

通过标准：

- 报价提交后锁定。
- 修改或补充必须留版本。
- 只能看本企业应标记录。

### 7. 评审专家

验收脚本：

1. 登录并查看我的评审任务。
2. 确认回避、纪律、保密要求。
3. 查看被分配的应标资料。
4. 按评分模板评分。
5. 提交评分并锁定。
6. 如需复评，由采购方授权后再操作。

通过标准：

- 只能看分配给自己的项目和评分范围。
- 提交后不能随意修改。
- 评分记录可审计。

### 8. 纪检/审计人员

验收脚本：

1. 登录系统。
2. 只读查看采购申请、询价、招标、报价、评审、定标、订单、结算、文件和日志。
3. 查询异常操作和敏感操作记录。

通过标准：

- 无新增、编辑、删除、审批、评分、定标按钮。
- 可查看完整日志。
- 报价保密期仍不能越权查看敏感内容。

### 9. 平台运营人员

验收脚本：

1. 维护商品分类和商品资料。
2. 上传商品图片和图文详情。
3. 设置销售定价。
4. 上架或下架商品。
5. 配置样板间和开业包。
6. 跟踪商城订单和售后。

通过标准：

- 商品中心和商城展示一致。
- 上架价格和定价报告一致。
- 样板间、开业包可生成商城采购动作。

## 七、为什么先做 R0 + R1

R0 和 R1 是后续所有阶段的前置条件。

R0 解决“到底还差什么”的问题。没有逐页矩阵，后续开发容易继续偏离 PDF，只能得到“功能很多但客户一看还是不像”的结果。

R1 解决“现有系统能不能被正常使用”的问题。当前用户已经明确反馈上传、图片、字段语言、删除、页面可用性等问题，这些问题不先处理，后续新增功能会继续堆在半成品体验上。

因此下一轮 Goal 建议只做 R0 + R1，不建议一次性跑完 R0-R10。

## 九、R1 详细范围

R1 不追求新建大模块，重点是把当前系统修到“可正常演示和 UAT 点击”的状态。

### 1. 中文化和显示修复

- 修复可见中文乱码。
- 清理页面中的英文状态、英文枚举、调试文本。
- 统一状态中文，例如草稿、待审批、已审批、已发布、已提交、已截标、已定标、已发货、已收货、已结算。
- 统一金额、日期、文件、图片的展示格式。

### 2. 文件和图片可用性

- 所有关键上传入口必须是真实文件选择器。
- 采购文件、报名资料、资质附件、响应文件、结算资料、发票、商品图片、封样图片、验收图片要能真实上传。
- 图片类文件要能在页面预览。
- 文件要能下载、替换、作废，并保留版本记录。
- 必传文件未上传时不能提交。

### 3. 主流程 CRUD 补齐

- 关键主数据支持新增、编辑、删除或作废。
- 对已进入流程的数据，不做物理删除，改用取消、作废、撤回、禁用等业务动作。
- 供应商、商品、采购申请、询价/招标、订单、结算等列表要有明确操作入口。

### 4. 页面入口和演示数据整理

- 商城不能是空页面，要有可点击商品、图片、价格、库存或可订购信息。
- 文件中心不能只列 PDF，要能展示图片类文件。
- 项目工作台、商城、供应商、采购、评审、结算、审计入口要清晰。
- 不同角色登录后看到的菜单和按钮要符合职责。

### 5. 浏览器验收

R1 完成后至少要用浏览器验证：

- 采购人员创建采购申请并上传附件。
- 供应商上传资质、报名资料、响应文件。
- 采购人员查看项目工作台和文件下载。
- 商品新增并上传图片，商城能展示图片。
- 酒店人员能进入商城选品。
- 文件中心能预览图片、下载文件、替换文件、作废文件。
- 审计角色只读查看日志。
- 无权限角色看不到敏感按钮或数据。

## 十、阶段验收统一口径

每个 R 阶段完成时，必须提交：

- PDF 页码覆盖说明。
- 页面和入口清单。
- API 和数据表变更清单。
- 角色流程验证说明。
- 新增、编辑、删除/作废、查询、重启留存验证。
- 文件和图片上传、预览、下载、替换、作废验证。
- 权限隔离和敏感字段隐藏验证。
- 自动化测试结果。
- 浏览器实测结果。
- 剩余未覆盖项清单。

不能只用“测试通过”作为完成标准。

## 十二、进入 R2 的条件

只有当以下条件满足后，才建议进入 R2：

- PDF 54 页逐页对标矩阵已完成。
- 现有系统主要页面不再存在明显中文乱码和英文业务状态。
- 关键上传入口可以真实上传文件。
- 图片上传和预览可用。
- 商城有基础商品和图片，不再是空壳。
- 关键数据具备编辑、取消、作废、删除或禁用动作。
- 采购、供应商、酒店、专家、财务、审计至少六类角色通过浏览器验收。

## 十三、生产化边界

即使完成 R0-R9，也不能自动判定为正式投产。正式投产至少还需要：

- 正式数据库和迁移验证。
- 集团 SSO 或统一身份接入。
- OA、ERP、WMS、财务、合同系统接口联调。
- 对象存储、杀毒扫描、备份恢复。
- 监控告警、日志归档、运维守护。
- HTTPS、Cookie Secure、安全基线和渗透测试。
- 客户 UAT 签字和上线预演。

R10 的目标才是进入正式试运行或投产评审。
