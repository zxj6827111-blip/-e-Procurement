# R8 UI 任务与消息补强验收报告

生成日期：2026-06-25

## 1. 本阶段结论

本阶段已将 R8 已完成的审批流、任务中心、消息通知能力补强为业务用户可见、可点、可验收的前端入口，并完成本地真实浏览器角色验收。

当前判断：

- 可进入客户 UAT：可以。范围限定为“我的任务、消息中心、审批规则维护、相关业务页入口”的业务验收。
- 适合小范围内网试运行：可以。前提是继续保持本地/内网 UAT 级运行约束，并保留人工监控与问题回滚。
- 仍不可正式投产：是。R8 仍未覆盖 R9 所要求的外部系统适配、对象存储、生产运维、安全基线、正式身份源和生产级部署治理。

## 4. 角色权限边界

已覆盖并验证的角色边界：

- 采购/集团采购管理：可查看本组织、本人项目范围内的采购、定标、结算、发票、付款任务；可处理当前节点分派给自己的审批任务。
- 供应商：只能看到本企业相关的退货、结算、发票等任务和消息；不能看到采购申请、付款审批等无权限消息。
- 专家：只能看到分派给本专家的评分任务；不能看到供应商退货、付款、采购审批任务。
- 审计：可只读查看任务、消息和审批规则轨迹；任务页无处理按钮；审批规则启停按钮禁用。
- 系统管理员：可查看并启用/停用审批规则；不显示“我的任务/消息中心”业务入口，直达任务页会回到驾驶舱，不能越权处理业务任务。
- 普通业务角色：不能维护审批规则；供应商读取规则接口返回 `WORKFLOW_RULE_READ_DENIED`。

后端同步补强：

- `apps/api/src/repositories/r8-workflow-task-repository.ts`：采购经办人的任务和消息读取从仅组织范围收紧为项目管理范围优先，避免同组织其他采购人员看到非本人项目待办。
- `apps/api/src/seed/data.ts`：系统管理员菜单移除 `myTasks`，保持“规则维护”和“业务处理”隔离。

## 8. 对 R0-R8 的兼容影响

- R1-R8 API 测试未回退，`test:api` 全量通过。
- 前端新增页面和入口均走 R8 workflow/task/notification API，不改变既有业务 API 的响应结构。
- 审批规则维护从旧接口展示切换为 R8 workflow 主源，减少旧源/新源不一致。
- 采购经办人权限收紧为项目范围优先，属于权限修正，避免同组织跨项目越权。
- 系统管理员从业务任务入口中移除，符合 R8 “系统配置维护”和“业务审批处理”隔离要求。

## 9. 风险与限制

- 本阶段为 R8 UI 补强和本地浏览器验收，不包含 R9 的生产运维、安全基线、对象存储、外部系统适配、正式 SSO、生产数据库迁移和灾备演练。
- 审计角色在 R8 规则中可作为只读/审计查阅节点展示，但运行时不允许审计执行审批动作；本阶段前端按只读处理，符合权限边界。
- 本地验收使用 `APP_ENV=test` 和 Mock 角色切换，仅用于 UAT/本地角色验证，不能作为正式身份认证方案。
- 浏览器验收数据包含多次准备过程中产生的额外待办/消息，这些记录用于验证列表、筛选和已读/未读状态，不影响主验收结论。

## 10. 下一阶段建议

建议可以进入 R9，但进入条件应限定为：R8 UI 不再新增大范围业务面，只做 UAT 问题修补。

R9 最小建议范围：

- 外部系统适配：SSO、ERP/财务、电子签章、消息通道、审计导出。
- 对象存储与文件治理：替换本地文件存储，补齐访问控制、生命周期和病毒扫描。
- 生产运维：环境配置、日志、监控、告警、备份恢复、灰度发布和回滚。
- 安全基线：正式认证授权、CSRF/XSS/文件上传/敏感字段脱敏/审计追踪复核。
- UAT 问题池：只接受客户验收中发现的 R8 UI 缺口，不再扩展新业务主流程。

结论：R8 UI 补强阶段已完成；当前适合客户 UAT 和小范围内网试运行，不适合正式投产。
