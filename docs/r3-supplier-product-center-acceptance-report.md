# R3 供应商与商品中心主源迁移验收报告

日期：2026-06-25

## 结论

R3 阶段验收通过。

本次已将供应商中心、商品中心、SKU、商品图片、供应商报价及报价明细、供应商限制、准入评审、封样、供应商评价等 R3 范围内的核心读写落点迁移到 R2/R3 正式业务表，并保留现有 API 与前端兼容结构。

该结论仅覆盖 R3 供应商/商品中心主源迁移，不代表全系统生产上线结论；商城订单、支付、结算、发票外部集成等后续阶段不在本次范围内。

## 实施范围

### 数据主源

- 新增 `R3SupplierProductRepository`，集中读写 `r2_suppliers`、`r2_supplier_qualifications`、`r2_supplier_admission_reviews`、`r2_supplier_seal_samples`、`r2_supplier_service_regions`、`r2_supplier_category_authorizations`、`r2_supplier_restrictions`、`r2_supplier_evaluations`、`r2_products`、`r2_skus`、`r2_product_images`、`r2_supplier_quotations`、`r2_supplier_quotation_items`。
- 扩展 `r2_suppliers` 字段：供应商类型、来源、统一社会信用代码、营业执照号、法定代表人、注册地址、经营范围。
- 新增 `r2_supplier_seal_samples`，承载供应商封样记录。
- 扩展 `r2_products` 字段：包装数量、起订量、最大订购量、税率、发票品名、税收分类编码、详情说明、验收指引、安装要求、服务区域 JSON。
- 报价明细正式落入 `r2_supplier_quotation_items`，包含采购价、销售价、税率、交付天数。

### API 行为

- 供应商准入、资料维护、资质替换、准入评审、限制/恢复、类目授权、封样记录均写入 R3 正式表。
- 报名提交前从 R3 供应商主表刷新供应商准入、限制和类目授权状态，受限供应商不能参与采购。
- 商品创建、编辑、上下架、报价提交、报价审批均写入 R3 正式表，并在查询前从正式表同步回兼容响应结构。
- 商品上架新增约束：供应商需已准入且未受限、SKU/规格完整、至少有一张图片、存在已审批且未过期报价。
- 履约评价从项目工作台和合同履约入口写入 `r2_supplier_evaluations`，并同步供应商评分到 `r2_suppliers.evaluation_score`。

## 验收覆盖

新增专项测试：`apps/api/tests/r3-supplier-product-center.test.ts`。

覆盖项：

- 供应商创建、资料字段、资质附件、准入评审、限制状态、封样记录写入正式表。
- 供应商重启后仍可从 R3 正式表读回资质、封样、限制状态和评分。
- 受限供应商报名被拦截。
- 供应商只能访问自身资料，审计角色只读，管理员被业务数据隔离。
- 商品、SKU、图片、报价、报价明细写入正式表。
- 缺图片/缺可用报价等不完整商品不能上架。
- 商品与报价重启后仍可从 R3 正式表读回并供列表接口使用。
- 供应商履约评价写入正式评价表，并更新供应商评分。
- 旧 Phase 2 报名约束测试已按“正式表为主源”语义同步测试前置数据，避免旧测试直接改内存状态绕过主源。

## 风险与边界

- R3 已覆盖供应商和商品中心主源迁移，但未扩展到完整商城订单、支付、结算、发票外部集成。
- 商品附件清单仍保持旧运行态兼容字段，R3 正式商品表当前主要承载图片主数据；如后续要把商品附件也作为正式主源，需要新增附件关联表。
- 当前上架规则按 R3 阶段最小可用约束实现，保留了既有测试中“未来生效价格可提前上架”的兼容语义，仅拦截已过期或未审批报价。
- Git 工作区无法通过 `git status` 正常识别，原因是当前 `.git` 目录不可用；本报告基于本地文件内容和验证命令结果。
