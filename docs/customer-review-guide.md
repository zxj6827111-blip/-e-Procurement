# 客户评审说明

## 1. 评审目的

本 Demo 用于让客户基于具体页面、流程、字段、权限和规则确认 MVP 是否可作为一期建设范围。评审重点不是确认生产技术实现，而是确认业务口径、权限边界、风控点和后续建模 / 接口 / 排期输入。

## 2. 客户需重点确认事项

| 序号 | 确认事项 | Demo 对应位置 | 建议确认结果 |
|---|---|---|---|
| 1 | 采购方式是否符合客户制度 | 采购项目与流程、采购需求与方式判断 | 确认 / 调整方式名称和适用条件 |
| 2 | 金额阈值是否后续由客户制度确认 | 项目详情、需求 Mock 数据 | 确认不在 Demo 中写死阈值 |
| 3 | 审批权责是否准确 | 我的待办、定标审批、异常查看审批 | 明确审批角色和组织层级 |
| 4 | 外部交易判定规则是否准确 | 外部交易备案、项目详情 | 确认强阻断范围 |
| 5 | 报价保密规则是否符合内控要求 | 报价保密与异常查看 | 确认截止前不可见对象和字段 |
| 6 | 异常查看审批是否符合管理要求 | 异常查看审批 | 确认申请字段、审批人、有效期和日志 |
| 7 | 专家抽取 / 指定 / 替换 / 回避规则是否符合制度 | 专家评审 | 确认抽取优先、指定理由、替换理由和回避规则 |
| 8 | 专家评分模板是否需要调整 | 专家独立评分、评分汇总 | 确认评分维度和权重 |
| 9 | 非最低价中选理由和审批是否符合要求 | 定标审批与结果通知 | 确认理由必填和审批链 |
| 10 | 合同系统边界是否准确 | 合同台账与履约 | 确认本平台只做采购侧台账和履约 |
| 11 | 财务、ERP、OA、主数据接口边界是否准确 | ERD / 接口建议 | 明确一期必须联调、建议联调、人工替代和二期预留 |
| 12 | 档案目录是否完整 | 项目档案与审计日志 | 补齐客户档案目录清单 |
| 13 | 审计日志是否满足监督需要 | 审计日志、异常查看日志 | 确认日志字段和保留要求 |
| 14 | 供应商视角是否完全隔离其他供应商 | 项目详情、公告 / 邀请、报名、报价、合同、评价 | 确认只展示本企业和必要数量提示 |
| 15 | 专家评分是否按专家 × 供应商建模 | 专家评审 | 确认 2 名专家 × 2 家供应商形成 4 条评分记录 |
| 16 | 系统管理员是否只做配置 | 工作台、基础配置 | 确认不进入供应商管理和采购实质内容 |
| 17 | MVP 验收范围是否可以接受 | 全部 Demo 页面 | 形成 M0 后续开发排期依据 |

## 3. 建议评审顺序

1. 使用“集团采购管理人员”视角查看驾驶舱和项目总览。
2. 使用“采购经办人”视角查看内部采购闭环和报价截止前保密。
3. 使用“供应商”视角查看本企业项目、公告 / 邀请、报名、报价、合同和履约反馈，确认其他供应商名称和明细隐藏。
4. 使用“评审专家”视角查看回避确认、保密承诺、供应商逐行评分表、本人评分和提交锁定。
5. 使用“纪检 / 审计人员”视角查看外部交易阻断、异常查看、档案和审计日志。
6. 使用“系统管理员”视角确认基础配置边界，不处理采购实质业务。

## 4. 评审结论建议

评审完成后建议形成三类结论：

- 已确认：可进入 ERD、接口评审和开发排期。
- 有条件确认：需补充制度、字段、审批权责或档案目录后进入排期。
- 暂缓确认：影响一期范围、合法合规边界或关键流程闭环的问题，需客户先决策。

## 5. 客户评审演示脚本

建议按以下顺序演示：

0. 项目详情工作台：进入“项目详情工作台”，切换“客房一次性用品采购项目”“上海滨江酒店食材供应商比选”“客房布草集中采购项目”，用同一页面展示采购申请、供应商准入、询价邀请、报名、报价、比价、定标、订单、收货、评价、结算资料、档案和日志。
1. 集团采购驾驶舱：说明项目分类、风险提醒、角色入口和一期边界。
2. 采购需求与方式判断：确认需求字段、金额阈值“客户制度确认”、采购方式建议和判断结果留痕。
3. 内部采购项目流程：先看“客房一次性用品采购项目”的截止前状态，再看“客房布草集中采购项目”的截止后完整闭环。
4. 供应商隔离：切换供应商视角，确认公告 / 邀请只显示本企业是否被邀请和供应商数量，报名、报价、合同、评价只显示本企业。
5. 报价截止前保密：切换采购经办人、集团采购管理人员、纪检 / 审计、专家和供应商视角，确认金额、响应文件和下载入口按角色隐藏。
6. 异常查看审批：演示发起申请、审批通过、授权范围内查看、未授权供应商拦截、未授权内容拦截、授权过期失效和日志记录；授权查看应展示文件名、大小、上传时间、Hash Mock、不可见内容、有效期和日志号。
7. 报价截止后汇总：演示报价锁定后采购经办人可按权限查看汇总；供应商仍只能查看本企业报价和结果。
8. 专家评审：切换专家本人视角，确认回避、纪律、保密承诺三步和供应商逐行评分表；再切换管理 / 审计视角看专家提交状态、供应商汇总、排名、异常、非最低价推荐、重评版本和报告冻结。
9. 定标审批：演示非最低价中选理由必填、审批中状态和结果通知留痕。
10. 管理员配置：切换系统管理员，确认只看到工作台、我的待办、基础配置，不显示供应商管理和业务项目指标。
11. 外部交易项目强阻断：确认无内部报价截止、无内部报价锁定；点击内部公告、报名、报价、专家评审、内部定标入口，确认弹窗拦截原因。
12. 合同台账与履约：确认本平台只做采购侧台账、履约节点、验收付款和评价，不替代合同系统。
13. 供应商评价：确认评价结果进入供应商档案，并可影响后续准入和品类授权。
14. 项目档案：确认 23 项必备目录模板、完整性检查、封存记录和 `p-ext` 补档申请。
15. 审计日志：确认报价查看、异常查看、专家评分、结果通知、档案补充等动作可追溯。

## 7. 酒店招采规范化闭环演示脚本

| 场景 | 演示项目 / 入口 | 关键确认点 |
|---|---|---|
| 供应商准入 | 项目详情工作台 - 供应商准入 | 展示资质初审、准入评估、供货区域、授权品类、封样记录、限制名单和供应商详情数据。 |
| 酒店耗材采购 | `p-pre` 客房一次性用品采购项目 | 采购申请明细、采购文件、邀请供应商、答疑、供应商报价；截止前采购方、审计方不显示 `amount`、`fileName`、`responseFileMetadata`。 |
| 食材供应商比选 | `p-food` 上海滨江酒店食材供应商比选 | 食材品类、冷链要求、比价报告、订单、异常收货、供应商评价、结算资料状态。 |
| 订单履约异常 | `p-food` 订单与收货区 | 数量不符、质量问题、延期交付、资料缺失、其他异常类型均按收货记录留痕。 |
| 审计追溯 | 纪检 / 审计角色进入项目详情工作台 | 审计只读查看归档项和日志；供应商、专家、系统管理员不得读取审计实质内容。 |

本轮演示边界保持为“酒店采购招采规范化小模块”。页面和接口不包含商城、购物车、支付、资金余额、授信、充值、CA、电子签章、投标文件加密、开标解密、远程异地评标、区块链存证、AI 串标分析或真实 ERP/WMS/OA 联调。

## 8. 第二轮客户评审验收清单

| 序号 | 验收项 |
