# 酒店集团内部采购规范化平台客户演示操作手册

> 适用环境：本地 UAT / Mock 演示环境。  
> 本手册用于客户演示、内部培训和需求确认，不等同于生产上线运维手册。

## 1. 演示前准备

### 1.1 访问地址

- 前端入口：`http://127.0.0.1:5174/`
- 后端健康检查：`http://127.0.0.1:3000/health`

打开前端后，如果已经登录，会进入“集团采购驾驶舱”；如果未登录，会进入登录页。

### 1.2 登录方式

系统支持两种演示登录方式：

| 登录方式 | 用法 | 适用场景 |
|---|---|---|
| 正式登录 | 账号为用户 ID，密码为 `pass-用户ID`，例如 `u2 / pass-u2` | 演示真实登录链路、会话、审计留痕 |
| 本地 Mock 登录 | 在登录页选择角色后点击“Mock 登录” | 快速切换角色、给客户演示权限隔离 |

演示时建议使用“本地 Mock 登录”，切换角色更快。登录后右上角会显示“姓名 / 当前角色”，点击该区域可进入角色切换页。

## 3. 角色功能总览

### 3.1 集团采购管理人

适合客户方采购管理部门负责人演示。

主要功能：

- 查看集团采购驾驶舱，掌握项目数量、风险、待审批、截止临近等信息。
- 查看采购需求、项目、供应商、采购文件、公告邀请、报名资料、报价保密、专家评审、定标审批、外部交易备案。
- 对关键流程进行审批或监督，例如需求审批、异常查看审批、定标审批、档案补档审批。
- 查看审计日志和项目档案，确认系统有留痕。

演示重点：

- 这是“管理和监督视角”，能看全局，但不应该替代专家评分，也不应绕过审批直接改业务结果。
- 可用于向客户确认集团层级、区域层级、酒店层级的数据范围。

### 3.2 采购经办人

适合演示主业务流程，建议作为第一主讲角色。

主要功能：

- 创建采购申请，填写使用部门、申请人、品类、预算、到货时间、收货地点和明细。
- 提交审批、审批通过、采购方式判定。
- 根据已审批需求发起项目。
- 编制采购文件，提交审核，发布并锁定。
- 发布公告或定向邀请供应商。
- 查看报名资料和提交状态。
- 在报价截止前只看提交状态，不看报价金额和响应文件。
- 截止后进行报价锁定、比价汇总、专家抽取、定标审批和结果通知。
- 在项目工作台生成采购订单、登记收货、处理异常、评价供应商。
- 归集项目档案并查看审计日志。

演示重点：

- 采购经办人是主线推进者，但很多节点受状态和权限约束。
- 报价截止前的保密边界是核心管控点。
- 定标、履约、评价、归档都形成审计痕迹。

### 3.3 酒店采购

适合演示酒店门店或区域单位的采购协同。

主要功能：

- 查看与本酒店相关的项目、履约订单、收货、结算和档案。
- 可参与采购需求、项目工作台、商城采购和收货。
- 关注“门店使用部门提出需求，酒店采购执行收货”的场景。

演示重点：

- 数据范围比集团角色窄，主要围绕本酒店组织。
- 适合讲“集团管规则，酒店执行业务”的权限分工。

### 3.4 酒店财务

主要功能：

- 查看履约、结算、资金和审计相关信息。
- 关注发票、结算资料和付款前置材料。

演示重点：

- 当前演示系统不做真实付款和财务核算，只登记采购侧结算资料状态。
- 财务系统、ERP、资金账户等属于后续接口或客户系统边界。

### 3.5 平台运营

主要功能：

- 查看和维护供应商档案、项目、履约、档案、审计。
- 在供应链商城中维护商品、上架、下架、场景模板、问卷等运营内容。

演示重点：

- 平台运营偏“运营维护”，不是采购审批人。
- 可用于演示商城和供应商运营能力。

### 3.6 供应商

适合演示外部供应商登录后的隔离视角。

主要功能：

- 查看本企业可参与的项目。
- 查看本企业供应商资料和准入状态。
- 查看本企业报名、报价、合同、订单、结算资料、评价结果。
- 只能看到本企业相关数据，不能看到其他供应商名称、报价、文件、评审意见和排名明细。

演示重点：

- 供应商视角是权限隔离演示重点。
- 对客户说明：供应商侧只看“自己是否被邀请、自己是否已报名、自己的报价和结果”。

### 3.7 供应商管理员

主要功能：

- 维护本企业资料、资质、联系人、供货区域、封样等。
- 确认采购订单。
- 上传发票、送货单、验收单等结算资料。
- 在商城中维护本企业商品、订单和发票。

演示重点：

- 与普通供应商相比，供应商管理员更偏企业侧管理和履约协同。

### 3.8 供应商报价人员

主要功能：

- 提交报名资料。
- 保存报价草稿、提交报价、撤回、重新提交。
- 上传响应文件或附件。

演示重点：

- 报价人员只负责报价业务，不应维护企业基础档案或查看其他供应商信息。

### 3.9 专家

主要功能：

- 查看“我的任务”和被分配的专家评审项目。
- 确认回避、纪律和保密承诺。
- 查看授权评审资料。
- 暂存评分、提交并锁定评分。

演示重点：

- 专家只看本人被分配项目和本人评分表。
- 专家之间评分互不可见。
- 提交后评分锁定，后续重评需要审批或留痕。

### 3.10 财务审核

主要功能：

- 查看履约与结算信息。
- 核验结算资料，例如发票、送货单、验收单。
- 对资料进行“核验通过”或“驳回重传”。

演示重点：

- 财务审核关注“资料是否齐全、是否满足付款前置条件”。
- 当前不做真实付款，只保留审核状态和留痕。

### 3.11 纪检 / 审计

主要功能：

- 只读查看采购需求、项目、供应商、采购文件、公告、报名、报价保密、专家评审、定标、外部备案、档案、审计日志。
- 查看异常查看审批、报价查看记录、专家评分记录、档案补档记录。

演示重点：

- 纪检 / 审计不修改业务数据。
- 重点展示“只读监督、全流程留痕、越权拦截可追踪”。

### 3.12 系统管理员

主要功能：

- 查看系统配置范围。
- 管理组织、账号、角色、菜单、权限与基础配置。
- 查看审批规则配置。

演示重点：

- 系统管理员不是采购业务人员。
- 系统管理员不应看到或修改供应商报价、专家评分、定标结果、履约评价等业务实质内容。

## 4. 系统主流程总览

完整内部采购闭环如下：

1. 采购经办人创建采购申请。
2. 采购经办人提交审批。
3. 集团采购管理人或授权审批角色审批需求。
4. 采购经办人进行采购方式判定。
5. 采购经办人发起项目。
6. 采购经办人编制采购文件，提交审核，发布并锁定。
7. 采购经办人发布公告或定向邀请供应商。
8. 供应商报名并上传资料。
9. 供应商报价人员保存、提交、撤回或重提报价。
10. 报价截止前，采购方只能看报名和提交状态，不看金额和响应文件。
11. 报价截止后，采购方锁定报价，查看汇总。
12. 采购经办人或集团采购管理人抽取、指定或替换专家。
13. 专家确认回避、纪律、保密承诺，完成评分并提交锁定。
14. 系统形成评分汇总、评审报告或比价结果。
15. 采购经办人创建定标审批，必要时填写非最低价中选理由。
16. 集团采购管理人审批定标结果。
17. 采购经办人发送结果通知，进行内部公示。
18. 采购经办人或集团采购管理人生成采购订单。
19. 供应商管理员确认订单。
20. 酒店采购或采购经办人登记收货，必要时登记异常。
21. 供应商管理员上传结算资料。
22. 财务审核核验结算资料。
23. 采购经办人提交供应商履约评价。
24. 项目档案归集、完整性检查、封存。
25. 纪检 / 审计查看审计日志和档案。

## 6. 按页面操作说明

### 6.1 集团采购驾驶舱

入口：左侧“工作台 / 集团采购驾驶舱”。

可看内容：

- 当前角色可见项目数量。
- 当前权限视角。
- 后端服务状态。
- 今日待办与站内消息。
- 风险和业务概览。

演示说法：

“驾驶舱不是所有人看到同一张表，系统会按当前角色和组织范围过滤项目、消息和待办。”

### 6.2 我的任务

入口：左侧“工作台 / 我的任务”。

可做动作：

- 查看当前角色待处理任务。
- 对审批类任务执行“同意”“驳回”。
- 对普通任务执行“完成任务”。

衔接关系：

- 采购需求提交后，会生成审批或处理任务。
- 定标、补档、结算等流程也会进入任务中心。

演示说法：

“业务页面负责产生业务动作，任务中心负责把动作推给对应角色。”

### 6.3 消息中心

入口：左侧“工作台 / 消息中心”。

可做动作：

- 查看当前角色可见消息。
- 标记单条消息已读。
- 将当前列表全部标记已读。

衔接关系：

- 公告发布、供应商邀请、结果通知、审批变更等会形成消息。

### 6.4 采购需求

入口：左侧“采购业务 / 采购需求”。

推荐角色：采购经办人 `u2`。

可做动作：

- 创建采购申请。
- 上传申请附件。
- 删除草稿申请。
- 取消未立项申请。
- 提交审批。
- 审批通过或驳回。
- 采购方式判定。

字段说明：

- 申请标题：客户能理解的采购事项名称。
- 使用部门 / 申请人：业务提出方。
- 采购品类：例如客房一次性用品、客房布草、食材供应。
- 预算金额：演示里用于流程判断和展示，不代表最终客户制度阈值。
- 外部交易备案路径：勾选后项目进入外部交易备案链路，不走内部公告、内部报价、内部评审。

前后衔接：

- 前一步：业务部门提出采购需求。
- 当前动作：采购经办人录入、提交、审批、判定方式。
- 后一步：项目立项。

### 6.5 项目立项

入口：左侧“采购业务 / 项目立项”。

推荐角色：采购经办人 `u2`。

可做动作：

- 选择“状态为方式已判定且审批通过”的采购申请。
- 填写项目名称。

## 8. 演示时的关键话术

### 8.1 平台定位

可以这样说：

“这是酒店集团内部采购规范化平台，重点不是替代公共资源交易平台，也不是替代合同系统或财务系统，而是把集团内部采购申请、供应商准入、采购文件、报名报价、专家评审、定标审批、履约评价、档案归集和审计监督串起来。”

### 8.2 报价保密

可以这样说：

“报价截止前，供应商可以看到自己的报价，采购方只能看到报名和提交状态，看不到金额和响应文件。确需异常查看时，必须走审批，并且限制对象、内容和有效时间。”

### 8.3 专家评审

可以这样说：

“专家只看到分配给自己的项目和自己的评分表。采购经办人可以看提交状态和汇总结果，但不能替专家修改评分。”

### 8.4 外部交易

可以这样说：

“依法必须外部交易的项目，本平台不走内部公告、内部报名、内部报价、内部评审和内部定标，只做备案、资料归集、合同台账、履约评价和审计留痕。”

### 8.5 系统管理员边界

可以这样说：

“系统管理员负责账号、角色、菜单、规则等配置，不参与采购业务实质处理，也不应该看到供应商报价、专家意见、定标理由等敏感业务内容。”

### 8.6 UAT 边界

可以这样说：

“当前是 UAT / Mock 演示环境，重点确认业务流程、角色边界、页面口径和数据结构。生产上线前还需要接入集团 SSO、正式数据库、文件服务、ERP / OA / 财务等外部系统，并做正式安全验收。”

## 9. 常见客户问题回答

### 9.1 供应商能不能看到其他供应商？

不能。供应商只看本企业报名、报价、订单、结算、合同和评价信息。其他供应商名称、报价、响应文件、专家评分和内部审批意见都不应展示。

### 9.2 采购方能不能提前看报价？

正常不能。报价截止前只能看报名和提交状态。若确需查看，必须通过“报价保密与异常查看”发起审批，审批通过后限对象、限内容、限时查看，并写入审计日志。

### 9.3 专家评分能否被采购方修改？

不能。专家评分由专家本人完成并提交锁定。采购方可以查看汇总和报告状态，但不能修改专家实质评分和意见。

### 9.4 系统是否支持外部招投标？

当前平台不替代外部交易平台。依法必须外部交易的项目走“外部交易备案”链路：记录外部平台、外部编号、公告材料、中标结果材料和后续采购侧台账。

### 9.5 系统是否能直接付款？

当前演示版不做真实付款。系统登记发票、送货单、验收单、结算资料状态和核验结果，真实付款、资金余额、财务核算需要对接财务系统或 ERP。

### 9.6 是否已经可以生产使用？

当前适合本地演示、UAT 和业务确认。生产使用前还需要完成正式身份认证、数据库、文件存储、审计策略、备份、接口联调和安全验收。

## 10. 演示注意事项

1. 优先用 `u2` 作为主线角色，因为采购经办人能串起最多业务流程。
2. 供应商隔离演示建议用 `u12` 或 `u3`，不要用管理员角色替代供应商视角。
3. 专家演示建议用 `u7`，当前有 `p-award` 的专家评分样例。
4. 外部交易演示一定使用 `p-ext`，避免把外部交易讲成内部招采。
5. 报价截止前保密演示使用 `p-pre`；完整闭环演示使用 `p-award` 或 `p-food`。
6. 如果客户问生产上线，明确说明当前是 UAT / Mock 演示环境，生产前需要正式集成和验收。
7. 演示过程中每个关键动作后，可切换到“审计日志”说明动作已留痕。
